# ZJU-AC

浙江大学「学在浙大」签到提醒与终端确认签到工具。终端输入学号密码，通过纯 HTTP 完成统一身份认证并轮询待签到活动，提供终端及桌面提醒。数字及 GPS 签到由用户在终端确认后尝试提交；整个程序无需安装、启动或保持浏览器。

这是独立实现的 Python 项目。GPS 功能目前为实验性实现，尚待真实活动验证；二维码及其他类型仅提醒，需在正常客户端完成。

## 快速开始（Windows / PowerShell）

先安装 Miniconda 或 Anaconda，在支持 conda 的终端中执行：

```powershell
cd 'D:\Personal Documents\ZJU-AC'
conda create -n zju-ac python=3.12 pip -y
conda activate zju-ac
python -m pip install -r requirements.txt
python -m zju_ac
```

按提示输入学号及统一身份认证密码；密码不会回显。程序跟随课程站的认证跳转，读取动态表单并通过 HTTPS 提交。登录成功后，每 15 秒查询一次签到；首次检测到待签到时提醒，数字及 GPS 签到还会在终端询问是否提交。按 `Ctrl+C` 退出并清理本次会话。

密码和 Cookie 仅保留在本次运行的内存中，不写入配置或日志。每次手动启动仍需输入学号密码；默认开启的看门狗会在父进程内存中保留本次输入，供工作进程恢复时重新登录。不应通过命令行参数、聊天或 Git 提供密码。

环境由 conda 管理，存放在 conda 的环境目录中；项目目录只保留源码、文档和依赖声明。后续启动无需重新安装：

```powershell
conda activate zju-ac
cd 'D:\Personal Documents\ZJU-AC'
python -m zju_ac
```

如果终端找不到 `conda`，请使用安装时提供的 Anaconda Prompt，或在其中运行 `conda init powershell` 后重新打开 PowerShell。

从旧版升级时，在已有环境中更新依赖即可；新版本不再使用 Playwright，也不提供 `--browser` 参数：

```text
conda activate zju-ac
python -m pip install -r requirements.txt
```

新版新增 `requests` 和 `beautifulsoup4` 依赖。程序会在请求学号密码前检查认证模块能否加载；缺少依赖时会提示安装命令及当前 Python 路径。请在运行程序的同一环境中执行安装命令。

## 常用命令

```powershell
# 离线演示通知，不登录、不访问网络
python -m zju_ac --demo

# 每 20 秒查询；未完成时每 60 秒重复提醒
python -m zju_ac --interval 20 --remind-every 60

# 登录后只查询一次，不询问或提交签到
python -m zju_ac --once

# 持续监控，但仅提醒，不询问或提交签到
python -m zju_ac --reminders-only

# 默认启用看门狗，工作进程异常退出后自动恢复
python -m zju_ac

# 如需关闭看门狗
python -m zju_ac --no-watchdog

# 仅输出终端提醒
python -m zju_ac --no-desktop --no-bell

# 参数说明
python -m zju_ac --help
```

默认每项活动在本次运行中只提醒一次；重启后重新提醒。指定 `--remind-every` 可重复提醒，轮询及重复提醒间隔至少 5 秒。每次轮询成功都会输出“监控正常”及当前待签到数量，包括没有待签到活动时；网络暂时失败时指数退避，最多等待 300 秒。会话过期、权限错误和未知接口结构会明确报错，不把失败解释为“没有签到”。

桌面通知受 Windows 通知设置、专注模式及系统支持影响；终端输出始终保留。桌面通知是补充渠道，建议保持终端可见。系统休眠、程序关闭或断网期间无法实时提醒。

## 看门狗

```powershell
python -m zju_ac

# 自定义重启等待时间和 10 分钟窗口内的重启上限
python -m zju_ac --restart-delay 10 --max-restarts 3

# 同时使用仅提醒模式
python -m zju_ac --reminders-only
```

看门狗默认开启，无需额外参数；`--no-watchdog` 可关闭，原有 `--watchdog` 参数仍兼容。只输入一次学号密码，由独立父进程监控工作进程；工作进程崩溃、非正常退出或会话失效时，默认等待 15 秒重新启动并登录。滚动 10 分钟内最多重启 5 次，达到上限后停止。普通轮询的短暂网络故障仍按原来的退避策略处理，不立即重启。

`--once` 单次查询和 `--demo` 离线演示直接运行，不启动看门狗。正常完成、Ctrl+C 和正常结束输入均不会触发重启。已识别的账号密码错误、缺少依赖、权限不足或协议不支持会停止并要求人工处理，避免反复认证。出现 OTP/TOTP 时仍需在终端输入验证码。

凭据通过进程启动通道在内存中传递，不写入磁盘、环境变量或命令行参数。子进程使用当前 Python 解释器，恢复后仍支持终端签到确认；不会重放崩溃前的确认或提交请求。重启后提醒去重状态也会重新开始，已完成活动仍以服务端本人状态为准。

确认提示出现后，输入 `y` / `yes` 并按回车提交决定；输入 `n` 或直接回车跳过。输入期间出现新的轮询日志也不需要重新输入，原来的提示仍在等待当前这一行。Windows 看门狗子进程会显式重新打开控制台输入，避免空设备被误判为可交互终端、显示提示后却无法接收输入的问题。更新后请退出旧进程并重新启动。

看门狗能恢复工作进程退出，不能阻止崩溃，也不监测进程卡死；父进程被结束、关闭终端、关机或系统重启后，需要重新启动程序。本功能不会安装开机任务或后台服务，退出时只清理自己创建的工作进程。

与厦大工具的其余功能差异见 [功能对比](docs/FEATURE_COMPARISON.md)。

## 数字签到

默认运行 `python -m zju_ac` 时，检测到数字签到会先发出提醒，再显示：

```text
确认提交《测试课程》课堂签到（编号 42）的数字签到？[y/N]：
```

- 输入 `y` 或 `yes` 后才会读取数字码并尝试提交；直接回车、输入 `n` 或其他内容均跳过。
- 数字码双通道：优先读取点名详情接口的 `number_code`；缺码、格式不匹配、接口无权限或暂时出错时，自动尝试课表日期接口的同一活动记录，查询日期取活动时间的 UTC 日期。不缓存数字码，不枚举或猜测数字码；缺少活动日期时不猜日期。
- 终端日志会显示取码来源，不输出实际数字码。两条通道均不可用时转为手动输入；会话失效则停止并要求重新登录，不误当成缺码。
- 接口未提供数字码时，终端会提示输入课堂公布的码（4–8 位 ASCII 数字，保留前导零）；直接回车取消。此步骤只会在你已确认该活动后出现。
- 同一活动在本次运行中只询问一次；跳过、取消或失败后不会反复弹出确认。需要再次尝试时，可重启程序或使用正常客户端。
- 等待终端输入期间继续轮询并提醒其他活动；有多项待确认时按顺序询问，每条提示包含课程、标题和活动编号。所有 HTTP 请求均在主线程执行，网络请求期间处理输入可能短暂延后。
- 提交前重新检查活动是否仍为同一课程的进行中数字签到，并核对本人状态；活动结束、本人已签/请假、缺少课程编号或无法取得本人记录时取消提交。
- 每次确认最多发送一次提交请求。提交后回查本人课程签到记录，只有 `on_call` / `on_call_fine` 才报告 `[签到成功]`，HTTP 200 本身不算成功。
- 网络超时或服务端错误导致结果不确定时，仅回查，不自动重发；显示 `[待核验]` 时请在畅课查看结果。关闭终端输入或退出程序会取消尚未执行的确认。

`--reminders-only`、`--once` 和 `--demo` 都不会提交签到。Windows 桌面通知用于提醒，确认操作在终端完成。

## GPS 签到（实验性）

默认运行 `python -m zju_ac` 即可。检测到 GPS 活动时，沿用终端、Windows 桌面通知及提示音，并显示包含课程和活动编号的确认提示：

```text
《测试课程》定位签到（编号 43）的 GPS 签到：将通过距离响应推算签到点，最多发送 4 次定位请求，探测也可能直接完成签到；不读取本机真实位置。确认尝试？[y/N]：
```

- 只有输入 `y` / `yes` 才发送定位请求；回车或其他内容跳过，同一活动每次运行只询问一次。等待输入时继续轮询其他活动，数字与 GPS 共用一个输入队列。
- 方法参考厦大的距离探测思路，不获取电脑或手机的真实 GPS。先向三个杭州附近、不共线的参考位置发送请求；只有服务端明确返回 `radar_out_of_scope` 及有效数值距离，才继续下一位置。
- 三份距离通过球面拟合与一致性检查后，再提交一次计算位置；每次确认最多四个定位写请求，任何探测请求也可能直接完成签到。不会遍历校区、无界尝试或自动重新执行整套流程。
- 每次定位请求前刷新活动并核对本人待签到状态；活动结束、类型变化、本人已签/请假、记录缺失或设备/权限限制时停止。
- 任意请求返回 HTTP 200 后，只回查本人状态，不再发送下一个位置；只有本人记录为 `on_call` / `on_call_fine` 才显示 `[签到成功]`。超时、服务端错误或无法解析提交结果时，同样只回查，显示 `[待核验]` 后不继续定位请求。
- 距离缺失、无效、含义不兼容或拟合失败会说明原因并停止本项尝试，继续其他活动的监控；会话失效仍交由现有登录恢复流程处理。日志不输出实际距离、计算坐标或服务端原始响应，位置仅保留在内存中。

**当前没有可测试的真实 GPS 活动，因此不能保证浙大现行接口仍支持距离返回。** 已验证公开接口调用依据和离线数学、协议、交互流程；历史脚本可行不代表当前平台或所有课程都可行。详细依据、算法调整和现场验证方式见 [GPS 可行性记录](docs/GPS_FEASIBILITY.md)。`--reminders-only` / `--once` 可保持只读运行。

## 当前协议与验证边界

- 登录入口：`https://courses.zju.edu.cn/user/index`，通过 `/api/profile` 确认登录成功。
- 待签到入口：`GET /api/radar/rollcalls`。已有浙大项目中该接口返回活动级 `rollcall_status`、本人 `status`、`course_title` 及 `rollcall_id`，因此首版采用它作为候选协议。
- 数字提交：`PUT /api/rollcall/{id}/answer_number_rollcall`，携带 `deviceId` 和 `numberCode`；同一次运行使用稳定的设备标识。
- GPS 提交：`PUT /api/rollcall/{id}/answer?api_version=1.1.2`，携带位置、精度和同一次运行稳定的设备标识；仅在明确确认后使用，定位写请求无自动重试。
- 结果确认：`GET /api/course/{course_id}/student/{student_id}/rollcalls`，按活动编号匹配本人的记录；最多查询 5 页、每页 100 条。数字码详情响应可能包含名单字段，程序不使用或保存这些字段，结果核验只查询本人记录。
- GPS、数字、二维码及其他类型统一提醒；实际覆盖范围取决于该接口向当前学生返回的活动。尚不能保证全部签到类型均被平台通过此接口下发。
- 已签、请假、尚未开始、活动结束、过期和超过截止时间的记录不提醒；无法识别的活动状态会报错，便于及时发现协议变化。
- 支持旧 CAS 的动态 `execution` 参数及 RSA 公钥加密，以及 `identity.zju.edu.cn` 的标准 Keycloak 用户名密码表单。依据实际跳转和表单识别协议，不固定认证提交地址或会话 token。
- 认证请求只允许 HTTPS 下的 `identity.zju.edu.cn`、`zjuam.zju.edu.cn`、`courses.zju.edu.cn`；保留证书验证，限制跳转次数，密码只提交一次。
- 标准 OTP/TOTP 二次验证可在终端输入动态验证码。图形验证码、滑块、扫码、JavaScript 加密的定制表单等验证方式尚未支持；遇到时明确退出，不会启动浏览器或尝试绕过验证。
- `--login-timeout` 设置认证流程的时间预算（默认 180 秒）；单次网络请求最多等待 15 秒。等待用户输入验证码时不强制中断输入，下一次请求前检查剩余时间。
- 登录、认证跳转、轮询、双通道取码、数字及 GPS 提交和结果回查统一使用直连会话：`trust_env=False`，并清空会话代理配置。忽略大小写形式的 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY` 以及 Windows 系统 HTTP 代理，避免失效代理端口导致请求失败。不修改系统代理或环境变量，也不全局替换 Requests 的会话类。
- 直连仍保留 HTTPS 证书验证；不自动降低 TLS 安全设置。`trust_env=False` 也会停用 Requests 对环境证书包及 `.netrc` 的自动读取，使用 Requests 默认的证书配置。
- 这里的直连指绕过应用层 HTTP 代理；VPN/TUN 等系统路由接管仍由操作系统和代理工具控制，如需绕过，应在对应工具中设置浙大域名直连规则。直连请求失败时检查校园网及目标站点连通性。

用户已反馈网络问题修复。数字与 GPS 签到完成离线协议及交互测试，**开发过程中尚未对真实浙大活动提交签到**；厦大的课表取码通道及 GPS 距离方法能否用于当前浙大活动，仍需实际验证。取不到数字码时可手动输入，不影响确认机制。若运行失败，请提供终端错误信息；如需协议样例，应先去除账号、Cookie、ticket、数字码、实际坐标和个人信息。

参考依据：[浙大官方登录说明](https://zuits.zju.edu.cn/90694/list.htm)、[浙大接口调用实例](https://github.com/5dbwat4/ZJU-live-better/blob/main/courses.zju/autosign.js)、[旧 CAS 协议参考](https://github.com/5dbwat4/login-ZJU/blob/main/src/zjuam.ts)、[XMU-AC 数字码接口参考](https://github.com/spicysuimai/XMU-AC/blob/master/auto_checkin.py)。项目独立实现，未放入厦大源码。

## 项目结构

```text
zju_ac/
  auth.py       纯 HTTP 认证、动态表单与安全跳转
  client.py     查询、数字/GPS 提交、本人状态核验及错误处理
  checkin.py    统一终端确认队列、补码及提交流程
  gps.py        GPS 距离验证、球面拟合及一致性检查
  models.py     活动解析与状态判断
  monitor.py    轮询、去重、重复提醒和退避
  network.py    统一直连会话配置
  notify.py     终端与桌面通知
  watchdog.py   独立进程监督、重启限额与终端恢复
  cli.py        终端入口
tests/          离线单元测试
```
