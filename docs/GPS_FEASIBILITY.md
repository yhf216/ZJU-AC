# GPS 方法与验证边界

更新日期：2026-10-15。当前使用 **配置中的已知经纬坐标单次提交**。此前三点测距及球面拟合已移除，不再依赖 `distance`，不再发送探测或空定位请求。

## 为什么改策略

[alkali210/XMU-Rollcall-Bot 的公告](https://github.com/alkali210/XMU-Rollcall-Bot#2026-10-12-雷达签到失效)记录，范围外提交不再返回距离，当前分支移除了依赖测距的 GPS 自动处理，提供手动提交已知坐标作为替代。

[KrsMt 原仓库 #35](https://github.com/KrsMt-0113/XMU-Rollcall-Bot/issues/35)的讨论同样指出范围外距离消失，以及空定位包策略失效，建议按实际上课地点提交经纬度。该讨论还链接了 [THU 雷达失败报告 #6](https://github.com/hot-YUser/auto-rollcall-thu-tronclass/issues/6)。这些是上游用户和维护者报告，并非本轮对浙大服务端的实测。

此前离线数学验证只能说明给定正确距离时能计算位置，不能证明服务端仍返回这些距离。继续修正拟合算法无法弥补输入信息缺失；本版本直接去掉这一前提。

## 采用的接口与参考数据

[ZJU-live-better 的 GPS 调用](https://github.com/5dbwat4/ZJU-live-better/blob/main/courses.zju/autosign.js)包含已知教学地点坐标及接口请求。本项目保留该请求形状，独立实现 Python 提交流程：

```text
PUT https://courses.zju.edu.cn/api/rollcall/{id}/answer?api_version=1.1.2
```

携带 `deviceId`、`latitude`、`longitude`、`accuracy` 等字段。同一次运行使用稳定设备标识。参考列表已放入根目录 `config.toml`，上游数组为 `[经度, 纬度]`，本项目采用显式字段避免填反；配置注释说明来源和按实际需要修改。

只提交 `gps.location` 指定的地点，不遍历全部参考点。用户可新增地点、修改名称和坐标，配置在下次手动启动生效。坐标不代表从设备读取的真实位置，也不是自动获取的教师签到中心；位置准确性由配置决定。

## 提交流程

1. 检测到 GPS 活动后先通知；手动模式等待 `y` / `yes` 加回车，自动模式经过 `checkin.gate` 后执行。
2. 刷新同一课程和同一编号的进行中 GPS 活动，并核对本人状态为 `absent`。已完成、请假、活动结束或无法确认时停止。
3. 向配置中的坐标发送一个定位写请求。坐标、精度和编号均先验证；未配置地点只提醒。
4. 范围外响应不论是否带距离都停止，并提示检查配置；设备、权限及其他拒绝同样停止，不改位置重试。
5. HTTP 200 或结果不确定时回查本人记录，只有 `on_call` / `on_call_fine` 才显示成功。超时、限流、服务端错误或未知写响应不自动重发。

每个工作进程内每项活动最多尝试一次。自动模式下看门狗恢复会重新检查服务端状态，去重状态不跨进程保存；此时仍待签到的活动可能再次尝试。程序不保存或输出坐标、距离及原始响应，不持久化账号密码和 Cookie。

## 已验证与未验证

离线测试覆盖配置选点和精度传递、纬度/经度范围验证、无确认不提交、自动门控和去重、无距离范围外响应、单次写入、本人状态核验、提交超时只回查，以及手动与自动模式的完整模拟 HTTP 流程。

尚无本轮可测试的真实浙大 GPS 活动，无法保证现行接口、参考点位置、课程范围、设备限制或状态更新延迟。没有把历史脚本的成功率、距离半径或平台版本描述作为保证。现场测试应以本人活动为对象，按实际位置修改配置，以程序回查及正常客户端记录共同核验。

失败时先记录终端的安全错误文本；如需协议样例，应去除账号、Cookie、票据、数字码、实际坐标、距离及个人信息。相关 issue 和解决方法索引见 [上游审查记录](UPSTREAM_REVIEW.md)。
