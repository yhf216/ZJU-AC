# 桌面 UI 设计方向

状态：后续桌面端的设计约束，本轮交付仍为终端核心功能。

目标是完整、精致的日常桌面应用。优先评估 PySide6 的 Qt Quick/QML 实现定制组件，复用 Python 业务核心；开始界面开发时先做可交互的高保真样稿，再确定组件和打包方案。

## 视觉方向

- 浅色以暖白背景、深灰文字与蓝色强调色为主；深色使用低饱和深灰背景。使用同一套语义色、间距、圆角和字体层级。
- 采用 8 像素间距体系、清晰留白和克制的边框与阴影。使用适合中英文混排的系统字体，支持高 DPI、文字缩放和键盘焦点。
- 主界面突出监控状态、最近核验成功时间和当前活动卡片；卡片用课程、签到类型、进度及下一步说明建立层级。
- 动画仅用于状态切换和反馈，尊重系统减少动态效果设置。状态不能只靠颜色区分。

## 必须清楚的交互

- 顶部常驻“正在监控 / 等待登录 / 网络异常”及暂停、恢复入口；避免用大量轮询日志占据主界面。
- GPS 地点由用户手动选择，当前选中地点始终可见。保留清晰的名称与坐标预览，不自动匹配课程或遍历地点。
- 将“等待人数”“等待第 2/5 轮取码”“提交中”“已确认成功”“未完成”“待核验”分别展示。读取重试与签到提交必须在界面上区分。
- 手动模式通过活动卡片上的确认、跳过及补码入口处理；纯界面模式不再依赖终端输入。
- 设置页显示取码轮数和最短间隔限制；保存是否需重启、当前监控是否采用新配置都应明确反馈。
- 设置页提供“导出诊断包”，完成后可打开所在文件夹。主界面保留简洁错误说明及处理入口。
- 托盘提供查看状态、打开窗口及退出；关闭窗口与结束监控的行为需明确可预测。

## 开始打包前

先将登录输入、状态事件和人工决定接入统一界面接口；网络请求留在工作进程或线程，避免阻塞 UI。处理好冻结程序的入口、看门狗启动方式、用户数据目录和配置迁移，再分别验证三平台的通知及安装包。视觉开发需覆盖正常、空列表、等待、失败、重连和待核验状态。
