# 与 XMU-AC 的功能对比

对比日期：2026-10-15。来源：[XMU-AC 仓库](https://github.com/spicysuimai/XMU-AC)、[主程序](https://github.com/spicysuimai/XMU-AC/blob/master/auto_checkin.py)。本项目独立实现，不引入厦大源码。

GPS 已改为提交配置中的已知坐标，支持手动或自动处理，等待真实活动验证，详见 [GPS 可行性记录](GPS_FEASIBILITY.md)。自动签到开关和默认直接签到的门控入口已加入根目录 `config.toml`；人数门控条件等待后续需求。Cookie/凭据持久化及控制面板仍不在当前补齐范围内。Cookie 保存登录会话令牌，学号密码配置是另一项功能。

## 其余主要差异

| 功能 | XMU-AC | 当前 ZJU-AC | 建议 |
| --- | --- | --- | --- |
| 按学期列出课程并逐课程扫描签到 | 有学期和课程查询，随后逐课程扫描 | 主要使用 `/api/radar/rollcalls` 聚合查询 | 后续补充辅助发现路径，验证聚合接口是否漏掉活动；不要照搬厦大学期默认 ID |
| 成功签到历史 | 保存最近 200 条成功记录 | 仅在终端显示本次结果，无历史文件 | 后续增加脱敏历史，不记录数字码、密码或 Cookie |
| 缺码诊断文件 | 按活动保存一次接口诊断；剔除大名单，不等同于完整脱敏 | 输出通道来源/失败信息，未保存诊断文件 | 如现场排障需要，再增加字段白名单和脱敏导出 |
| 终端统计仪表盘 | 显示运行时长、课程/查询数量和最近事件 | 每次轮询成功输出数量，另有事件日志 | 可后续增加简洁统计；这是终端展示，区别于独立控制面板 |
| 单条异常活动隔离 | 缺失状态限次重试，避免单条记录无限处理 | 遇到未知活动结构明确报错并停止 | 后续可隔离异常记录、继续监控已识别活动；不要把未知状态默认当作可以提交 |
| 会话失效后恢复 | 内置重试/重新登录 | 默认看门狗可重新登录；关闭后提示退出 | 已实现，保留认证失败的重试限制 |
| 数字码双通道、直连代理隔离 | 有 | 已有，且支持临时失败切换及手动补码 | 无需重复迁移 |
| 本人状态回查 | GPS 提交后回查；数字分支主要检查 HTTP 状态 | 数字及 GPS 提交后回查本人记录，结果不确定时不重发 | 已覆盖，保留当前核验机制 |
| GPS 方法 | 厦门两点平面圆交点法，依赖返回距离 | 已移除测距；只向配置选定坐标提交一次，支持人工确认或自动模式 | 新上游报告范围外不再返回距离，见审查记录 |
| 配置与自动开关 | 有自动、门控及配置 | 根目录 TOML 配置统一管理运行参数，自动开关默认关闭 | 人数/比例等门控待后续指定 |
| 离线测试 | 有门控/状态测试 | 已有认证、网络、数字/GPS 确认、轮询与看门狗测试 | 已覆盖 |

这里列的是功能差异，并不意味着所有厦大实现都应原样移植。看门狗已完成；当前优先验证 GPS 兼容性，后续可考虑异常记录隔离与活动发现覆盖、脱敏历史与诊断、终端统计。

## 本轮看门狗实现

- `python -m zju_ac` 默认启用独立父进程；根目录配置的 `watchdog.enabled = false` 可关闭。工作进程使用当前 Python 环境和同一终端；单次查询和离线演示直接运行。
- 异常退出或会话失效后，默认等待 15 秒重启；滚动 10 分钟内最多重启 5 次。
- 正常结束、Ctrl+C 或终端输入结束不重启；已识别的认证、依赖、权限和协议问题要求人工处理。
- 学号密码在父进程内存中保留，使用进程启动通道交给子进程；不写入文件、命令行参数或环境变量。需要额外动态验证码时仍需在终端输入。
- 重新启动恢复登录和监控；手动模式重新确认，自动模式重新检查服务端状态后处理待签到。不会重放旧的输入队列，但自动模式的活动去重状态不跨工作进程保存。
- 父进程退出时只清理自己创建的工作进程；不扫描或结束其他 Python 程序。
- 看门狗用于恢复工作进程退出，不能阻止崩溃，也不负责系统重启、父进程被结束、终端关闭或进程卡死的自动恢复。未安装开机任务或后台服务。
